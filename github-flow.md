# GitHub flow

**Os sete passos do GitHub Flow**
1. Criar uma branch
2. Fazer alterações
3. Realizar commits
4. Abrir um pull request
5. Revisar e testar
6. Fazer o merge
7. Apagar branch

**Por que não editamos direto na main?**

Não editamos diretamente na main pois ela representa a versão principal e mais estável do projeto. Trabalhar em outras branches
permite testar mudanças, corrigir erros e revisar o código antes de integrá-lo, evitando problemas e garantindo mais segurança.

**O que significam o vermelho e o verde no diff?**

No diff, a cor vermelha significa linhas de código que foram removidas ou substituídas e a cor verde representa as novas linhas
adicionadas. As cores facilitam a identificação e revisão das alterações realizadas em um arquivo.
